The AI control plane for complex systems.

Olymp is the runtime layer of the four-system cognitive stack (Mnemos · Chronos · Nous · Praxis). It drives the closed loop observe → understand → decide → act → learn end-to-end, with a single audit trail across every system.

Run the demo github.com/felixgeelhaar/olymp

Scenario

Two services start misbehaving. Watch Olymp react.

The reference demo boots two deliberately-broken sample services alongside the cognitive stack and pipes their Prometheus metrics into Chronos. As the failure pattern builds in the dashboard, Olymp's loop pulls the same observations through every cognitive layer and writes the outcome back into Mnemos.

flaky-payments

Error rate climbs from 2% baseline to 40% over three minutes. Visible in Grafana, ingested into Chronos via the prom2chronos bridge.

slow-checkout

Request latency drifts upward 60ms / minute. Capped at 2.5s p99. The kind of regression no binary alarm catches.

Olymp loop

Each explain or remediate intent runs the full cognitive loop. Provenance touches every layer; Mnemos records the outcome.

What each stage does

observing
Olymp asks Mnemos for active claims about payments-latency. Returns the SLO claim, the rollback hypothesis, and the service ownership graph.
understanding
Olymp asks Chronos for signals on the demo scope. prom2chronos has been posting payments_error_rate + checkout_p99_latency_seconds observations every 10s; Chronos's compute pipeline derives spike / drift signals from the time series.
deciding
Olymp submits the merged context (memories + signals) to Nous via POST /v1/extract. Nous extracts commitments, records a decision, returns its decision_id.
acting
Olymp sends an ActionRequest to Praxis. The action lands at the registered capability handler — in production, that's where the rollback / restart / page actually executes.
learning
Olymp writes the outcome back to Mnemos as a structured event. The next iteration's observing stage will surface it. The loop is closed.

Architecture

Five containers, one Docker network, real upstream binaries.

Nothing is mocked. Each cognitive layer runs the same image you'd deploy in production, against a shared Postgres. Olymp speaks each layer's real HTTP API; adapters translate Olymp's port verbs to the actual surface so each service stays usable on its own.

Run it

One script. Five minutes.

Requires Docker (with Compose v2), jq, and curl. Configured via deploy/.env.

git clone https://github.com/felixgeelhaar/olymp.git
cd olymp
./deploy/demo-full.sh

What the script does:

  1. Builds a local olymp:demo image.
  2. Boots the cognitive stack, the two broken sample services, Prometheus 2.55, Grafana 11.3, and the prom2chronos bridge.
  3. Waits for /healthz, then seeds Mnemos with three baseline claims.
  4. Submits one explain and one remediate run, prints the provenance chain.

While it's running, open:

localhost:3000

Grafana — anonymous viewer enabled. The Olymp Demo — Broken Services dashboard refreshes every 5s.

localhost:9090

Prometheus UI. Try payments_requests_total or histogram_quantile(0.99, …).

localhost:8080/v1/runs/stream

SSE feed of every Olymp run state change — connect from a terminal with curl -N.

Note. Chronos's pattern detection runs against the observations prom2chronos posts; signals appear once enough datapoints accumulate (typically a couple of minutes after the bridge starts). The Olymp loop keeps running on the observations themselves in the meantime.

Tear down

docker compose -f deploy/docker-compose.yml --env-file deploy/.env --profile demo down -v

The cognitive stack all four open-source

Olymp's job is to drive the loop. The intelligence lives below.

Mnemos

Memory. Local-first evidence layer. Extracts structured claims from text, detects contradictions, returns query answers with full evidence traceability.

Chronos

Time. Pattern detection over time-series data. Ingests observations, derives spike / drift / seasonality signals.

Nous

Decisions. Commitment extraction, risk evaluation, intervention generation. Audit-grade decision trail.

Praxis

Execution. Three verbs (ListCapabilities, Execute, DryRun). Idempotency, policy gating, replay-from-audit.
